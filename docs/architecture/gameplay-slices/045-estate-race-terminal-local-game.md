## Граница инкремента

S6 добавляет game-owned terminal outcome. После завершения банкротства сервер
выбирает из ограниченной `state.players` record-map участников со статусом
`active`. Результат размера один атомарно записывает идентичность единственного
участника в `state.public.outcome`, переводит ход в `terminal`, очищает каталог
действий и выпускает одно финальное событие. Результат размера два и больше
возобновляет обычное сохранённое продолжение.

Отдельная копия статусов, ручное действие «назначить победителя» и клиентское
вычисление победы не вводятся. Exact retry возвращает прежнюю квитанцию и не
публикует победу повторно.

## Контроль отсутствия дрейфа в платформу

Понятия активного участника, банкротства, победителя и причины окончания
остаются полями и значениями Estate Race. Общие `core.entities.select/each`,
`core.state.patch`, `turn.phase.select` и `core.event.emit` работают только с
объявленными типами и не получают предметной ветки, импорта либо `gameId`.
Player Web показывает только подтверждённый outcome и пустой server-declared
каталог действий.

## Наблюдаемый результат

- переход `3 → 2` не завершает партию;
- переход `2 → 1` через долг участнику и долг банку объявляет точного
  оставшегося победителя ровно один раз;
- банковская multi-lot ликвидация заканчивается до проверки победителя;
- `eliminated` больше не получает ход, ставку, запрос или торговую реакцию;
- terminal snapshot не содержит изменяющих действий, а прежние action IDs
  отклоняются до изменения состояния;
- UI и DOM показывают победителя из server-owned outcome.

## Ограниченный полный transcript

Интеграционная фикстура задаёт допустимое начальное состояние поздней партии в
скомпилированном game manifest до создания сессии, а затем проходит только
обычные Game Intent до terminal outcome. После создания сессии тест не правит
состояние вручную. Начальная, средняя и поздняя фикстуры остаются проверочными
данными пакета, а не вторым runtime или альтернативным языком правил.

## Внешний блокер готовности ИИ

ADR-060 требует `config.players.agentSeats`, session binding и
детерминированный fallback для ИИ-мест. На текущем commit такого поля нет в
канонической game-manifest schema и нет session/runtime реализации agent seat;
существующий top-level `agentRuntime` описывает иной AI-driven/hybrid режим.
Estate Race не добавляет его как ложную замену и не расширяет общую схему в
игровом срезе. После завершения terminal outcome программа честно остаётся
заблокированной для agent-readiness до результата отдельной платформенной
задачи ADR-060.

## Приёмка и остановка

Replay 49/49 доказал `3 → 2`, обе ветви `2 → 1`, exact retry, банковскую
multi-lot цепочку, попытку действия после terminal и ограниченный transcript
без post-create patch. Plugin 30/30 и typecheck проверили outcome, пустые
действия и fail-closed отображение. Production browser flow 8/8 прошёл
банкротство до видимого итогового экрана и пустого DOM-каталога.

Немедленная остановка нужна, если terminal outcome требует изменить Mechanics
schema/runtime, общую проекцию, player core или добавить предметную ветку.
S6 не объявляется полностью готовым к ИИ или сети до реализации их принятых
общих контрактов; локальная terminal-механика не должна ждать этих зависимостей.
