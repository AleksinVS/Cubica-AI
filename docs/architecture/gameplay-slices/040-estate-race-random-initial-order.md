# GSR-040: Estate Race — случайный начальный порядок S1

- **Дата:** 2026-08-10
- **Статус:** Completed (S1, 2026-08-10)
- **Предусловие:** завершены GSR-037–039; P-01 остаётся отдельным продуктовым воротом
- **Архитектура:** ADR-024, ADR-030, ADR-058, ADR-073, ADR-085, ADR-096,
  ADR-102

## Граница инкремента

Инкремент завершает S1 однократным серверным жребием для всех фактических
участников сессии. Обычное внешнее действие `session.setup.finalize` явно
запускается через интерфейс; скрытого hook при создании сессии нет. Игра
объявляет `state.players` как ограниченную record-map коллекцию ёмкостью шесть
и использует существующие общие операции выбора и порядка без теневой копии
участников.

## Реализованная семантика

- Начальная фаза — `setup`, а единственное доступное действие —
  `session.setup.finalize` без `playerId` в запросе клиента.
- Ведущий guard проверяет `public.setupComplete = false` и фазу `setup` до
  первого обращения к случайности.
- План выбирает всех фактических участников со статусом `active` с допустимой
  мощностью `2..6`. Поле `status` одинаково у всей выборки, поэтому
  `core.entities.order` разрешает полную ничью через `server-random` с
  game-owned purpose `estate-race.setup.participant-order`.
- Одна транзакция записывает `result.ids` в `public.turn.order`, первый id — в
  `activePlayerId`, меняет фазу на `roll`, устанавливает
  `public.setupComplete = true` и публикует действие `turn.roll`.
- Последующая ротация, дубли и диспетчер приземления продолжают использовать
  тот же `public.turn.order`; копии номера порядка в участниках и
  `core.entities.each` нет.

## Доверие, повтор и атомарность

Результат всегда является перестановкой точного набора ключей
`state.players`. Пакетный replay доказывает это отдельно для двух и шести
участников. Точный повтор принятого `commandId` возвращает сохранённую
квитанцию и не расходует новую случайность. Новый setup-command после
завершения отклоняется ведущим guard до случайности и не меняет состояние или
версию.

Общий admission разрешает whole-`players` storage только публичной
типизированной record-map коллекции. Entity-коллекции, широкий endpoint и
actor/server-аудитории на том же корне продолжают отклоняться; закрытая модель
игрока не допускает необъявленные поля.

## Интерфейс

Модуль поля только показывает серверную фазу `setup` как «определение
порядка» и передаёт объявленное действие. Browser flow нажимает кнопку через
обычный DOM, проверяет отсутствие `playerId`, получает перестановку и первого
активного участника, затем выполняет реальный `turn.roll` независимо от того,
кто выиграл жребий. Клиент не вычисляет и не сохраняет порядок.

## Проверка и продолжение

Authoring и опубликованный модуль выпускаются штатными генераторами.
Пакетный replay покрывает 2/6, exact retry, новый отклонённый command и
сохранение дальнейшей семантики хода; plugin tests покрывают display-only
setup. GSR-037–039 остаются историей последовательной реализации, а этот GSR
закрывает последний технический критерий S1.

Следующий milestone программы — S2: отказ от покупки, последовательный
аукцион и полная рента без застройки. P-01 не является долгом S1: это
отдельный продуктовый ворот окончательного содержания и каталога.
