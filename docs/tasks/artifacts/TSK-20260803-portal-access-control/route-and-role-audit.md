# Проверка маршрутов и роли портала

Дата: 2026-08-27. Базовая версия: `main` на `c5241b2`.

## До исправления

- `order`, `purchase` и `link` использовали стандартные core routers Strapi со всеми
  CRUD-маршрутами. Их доступность зависела от настроек роли вне Git.
- `PUT /orders/:documentId/status` менял произвольный заказ.
- `GET /robokassa/payment-link` выбирал заказ без владельца.

Снимок конкретной панели Strapi отсутствует в репозитории и не является переносимым
доказательством для нового VPS.

## После исправления

Фактическая фабрика установленного `@strapi/strapi` `5.10.2` вернула:

```text
order:[{"method":"POST","path":"/orders","handler":"api::order.order.create"}]
purchase:[]
link:[]
```

Пользовательские маршруты остаются отдельными:

- `GET /purchases` — контроллер выбирает записи по `ctx.state.user.id`;
- `POST /links/generate` — покупка выбирается одновременно по `documentId` и владельцу;
- `GET /robokassa/payment-link` — заказ выбирается одновременно по `documentId` и
  владельцу;
- `POST /orders/payment-stub` — требует аутентифицированного пользователя и серверный
  `PAYMENT_STUB_ENABLED=true`;
- `POST /robokassa/result` — публичен по назначению, но до БД требует настроенный секрет,
  допустимый вход и корректную подпись.

Таким образом, выдача лишнего права в панели не может восстановить отсутствующие core
routes. Для оставшихся custom actions панель должна дать только права, нужные тестовому
сценарию; авторизация объекта всё равно выполняется контроллером.

## Проверки

- `npm run test:portal-rules` — `35/35`;
- отсутствующий секрет, неверный формат и неверная подпись callback — отказ до БД;
- чужой и отсутствующий заказ при генерации платёжной ссылки — одинаковый `404`;
- корректный callback создаёт покупку, повторный не создаёт её второй раз;
- production Next.js build — успешно, прежние тестовые логин и пароль отсутствуют;
- независимое повторное Sol high security review — `PASS`.

## Остаточная проверка окружения

Перед доступом к тестовому VPS извне оператор должен подтвердить реальные значения
`ROBO_PASSWORD2`, `PAYMENT_STUB_ENABLED`, `PORTAL_TEST_CORS_ORIGIN` и выполнить smoke с
двумя пользователями. Это проверка развёртывания, а не недостающая кодовая граница.
