# Пробный запуск «Карт, денег, поездов»

Руководство разделяет три режима. Для продуктовой и визуальной проверки
используется изолированный предпросмотр нормативной игры с реальной картой,
25 точками, десятью начальными дорогами, 174 грузами, 34 новостями и
описаниями десяти стран. Mock-игра сохраняется только как регрессионный стенд
механики и постоянного хранения. Отдельный автоматический сценарий проверяет
два ограниченных пути реального содержимого.

Нормативный пакет пока нельзя публиковать как обычную игру: он намеренно
заблокирован до принятия геометрии областей, визуального подтверждения
начальной сети и новых итоговых окон. Партия продолжает работу с сохранённого
игрового снимка и не хранит состояние генератора. Локальный предпросмотр не
снимает оставшиеся содержательные и визуальные ограничения с исходного пакета.

## 1. Что будет запущено

Нужны три локальных процесса:

1. **PostgreSQL** — база данных, в которой постоянно хранится сессия.
2. **Runtime API** — сервер правил: он проверяет действия, меняет деньги,
   транспортную сеть и фазы, затем сохраняет результат.
3. **Player Web** — браузерный общий экран ведущего с обычными панелями и
   интерактивной картой Phaser.

База слушает только локальный адрес компьютера. Регрессионная mock-игра
открывается по адресу:

```text
http://127.0.0.1:3000/?gameId=cards-money-trains-mock
```

На экране должна быть заметна маркировка `MOCK — только разработка`. Если её
нет, не проводите пробную партию: вероятно, открыта другая игра.

Реальная игра открывается не по постоянному публичному адресу, а через
изолированный предпросмотр из раздела 3.4. В нём не должно быть метки `MOCK`
и узлов `A–F`.

## 2. Предварительная проверка

Откройте терминал в корне репозитория `/home/abc/projects/Cubica-AI` и
выполните:

```bash
node --version
docker version
```

Нужен Node.js версии не ниже `22.7.0` и работающий Docker. Если зависимости
репозитория ещё не установлены, сначала согласуйте установку с PM. После
согласования стандартная команда:

```bash
npm install
```

Дальше понадобятся два открытых терминала в корне репозитория. База данных
работает в фоне и отдельного терминала не требует.

## 3. Первый запуск

### 3.1. Создать постоянное хранилище PostgreSQL

Эта команда создает именованный том Docker — постоянную область данных, которая
не исчезает после обычной остановки контейнера:

```bash
docker volume create cubica-cmt-pgdata
```

Запустите PostgreSQL 17:

```bash
docker run -d \
  --name cubica-cmt-postgres \
  -e POSTGRES_USER=cubica \
  -e POSTGRES_PASSWORD=cubica_local_only \
  -e POSTGRES_DB=cubica \
  -p 127.0.0.1:55432:5432 \
  --mount type=volume,src=cubica-cmt-pgdata,dst=/var/lib/postgresql/data \
  --health-cmd "pg_isready -U cubica -d cubica" \
  --health-interval 2s \
  --health-timeout 5s \
  --health-retries 20 \
  postgres:17
```

Подождите, пока база станет готова:

```bash
docker inspect --format '{{.State.Health.Status}}' cubica-cmt-postgres
```

Нормальный ответ — `healthy`. Если пока показано `starting`, подождите несколько
секунд и повторите проверку.

### 3.2. Запустить сервер правил

В первом терминале задайте локальную базу, примените схему хранения и запустите
сервер:

```bash
export SESSION_STORE=postgresql
export DATABASE_URL='postgresql://cubica:cubica_local_only@127.0.0.1:55432/cubica'
export PORT=3001
npm run migrate:sessions --workspace @cubica/runtime-api
npm run dev --workspace @cubica/runtime-api
```

Терминал должен остаться открытым. Сообщение
`runtime-api listening on :3001` означает, что сервер запущен.

### 3.3. Запустить общий экран ведущего

Во втором терминале выполните:

```bash
RUNTIME_API_URL=http://127.0.0.1:3001 \
PORT=3000 \
NEXT_IGNORE_INCORRECT_LOCKFILE=1 \
npm run dev --workspace @cubica/player-web
```

Терминал также должен остаться открытым. После сообщения о готовности откройте:

```text
http://127.0.0.1:3000/?gameId=cards-money-trains-mock
```

При первом открытии браузер автоматически создает сессию и сохраняет её
идентификатор в локальном хранилище сайта. Отдельно создавать сессию командой не
нужно.

### 3.4. Открыть реальную игру для визуальной проверки

Сначала убедитесь, что Runtime API и Player Web уже работают. Затем проверьте
безопасность запуска на общем компьютере:

```bash
skills/C_low-memory-host-operations/scripts/preflight.sh
```

Не открывайте дополнительный браузер, если проверка сообщает о нехватке памяти
или занятом swap. После успешной проверки соберите только игровой плагин и
подготовьте реальный предпросмотр:

```bash
node scripts/manifest-tools/build-player-web-plugin-bundles.cjs \
  --game cards-money-trains

PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/snap/bin/chromium \
node games/cards-money-trains/tools/prepare-local-preview.mjs \
  --runtime-url http://127.0.0.1:3001 \
  --player-url http://127.0.0.1:3000 \
  --open
```

Подготовщик создаёт копию нормативного пакета под `.tmp/editor-worktrees`,
создаёт сессию в новом браузере и открывает общий экран ведущего. Исходный
манифест не меняется и остаётся закрытым для публикации.

Перед визуальной проверкой убедитесь:

- показаны терминалы `1–23`, `π` и полустанок `9¾`, а не `A–F`;
- видны десять коричневых железных дорог со шпалами;
- подключённые терминалы `1–9`, `π` и `9¾` зелёные, остальные серые;
- подложка не приглушена и совпадает с авторской картой;
- карта масштабируется и перемещается без рассинхронизации дорог и станций.

Закрытие окна останавливает только браузер предпросмотра. Runtime API,
Player Web и сохранённые сессии продолжают работать.

## 4. Проведение пробной mock-партии

Перед началом убедитесь в трех признаках:

- заголовок — «Карты, деньги, поезда»;
- видна маркировка `MOCK — только разработка`;
- показаны тестовая транспортная карта и кнопка подтверждения команд.

Дальше ведущий использует кнопки группы текущей фазы. Строительство использует
фактические узлы и дороги из текущей сессии; движение позволяет выбрать
локомотив на карте и дорогу, а загрузка, сцепление, отцепление и доставка
показывают текущие публичные грузы и активную технику в обычной клавиатурной
форме. Интерфейс намеренно не решает, допустима ли выбранная комбинация:
сервер проверяет фазу, состояние, узел, сцепление и закрытия и атомарно
отклоняет неверную операцию. Динамический рынок и полный ручной проход всех
фаз ещё остаются в `LEGACY-0058`. В тестовом цикле последовательно проходят настройка, новость,
обслуживание, рынок, грузы, операции, строительство и итоги хода. Игра не
заканчивается по номеру хода: завершение запрашивает и отдельно подтверждает
ведущий.

Для пробной приемки полезно проверить:

- начало игры клавишей `Enter`, а не только мышью;
- один успешный рыночный платеж и один отказ из-за недостатка денег;
- загрузку, сцепление, движение и доставку груза;
- несколько строительств до отдельного завершения фазы; разрешены и проверены
  оба порядка — «дорога → полустанок» и «полустанок → дорога»;
- для дороги — выбрать две станции, нажать «Рассчитать маршрут», сверить
  зелёную временную линию и цену, затем подтвердить строительство; после
  изменения станции прежний расчёт должен исчезнуть;
- обновление страницы в середине хода;
- остановку и возобновление по следующему разделу;
- в доступной игровой фазе открыть кнопку «Деньги», заполнить начисление и
  списание одной команды, применить строку и убедиться, что официальный
  баланс обновился только после ответа сервера;
- запрос завершения, его отмену и последующее подтверждение;
- после подтверждения увидеть два отдельных рейтинга — перевозчиков и
  паровозных гильдий, итоговую формулу и цены техники; закрыть окно и повторно
  открыть его кнопкой «Итоги».

## 5. Остановка без потери сессии

1. В терминале Player Web нажмите `Ctrl+C`.
2. В терминале Runtime API нажмите `Ctrl+C` и дождитесь сообщения об остановке.
3. Остановите базу:

```bash
docker stop cubica-cmt-postgres
```

Не удаляйте контейнер и том `cubica-cmt-pgdata`. Обычная остановка сохраняет
всю сессию.

## 6. Возобновление сохраненной сессии

Сохранённая сессия закрепляет `bundleHash` — отпечаток неизменяемого пакета
правил — и канонические байты этого пакета в PostgreSQL. Перезапуск базы и
сервисов на той же версии кода восстанавливает партию без потери состояния.

До сохранения текущего `1.0.1` как замороженного исполняемого снимка
(`LEGACY-0072`) не обновляйте Mechanics-схемы или код исполнителя между
остановкой и продолжением важной тестовой партии. Сервер уже выбирает версии
по точному реестру и не подменит правила молча, но предреестровый `1.0.0`
намеренно доступен только как архив: его точный исполняемый корпус не был
сохранён. Обычное изменение игровых файлов также применяйте только после
завершения текущей проверки и создания новой сессии.

Запустите базу:

```bash
docker start cubica-cmt-postgres
```

Убедитесь, что она готова:

```bash
docker inspect --format '{{.State.Health.Status}}' cubica-cmt-postgres
```

Затем снова выполните команды разделов 3.2 и 3.3. Откройте тот же адрес в том
же браузере и в том же профиле. Player Web прочитает сохраненный идентификатор
сессии и запросит её актуальное состояние из PostgreSQL.

Если открыть игру в другом браузере, другом профиле или приватном окне,
автоматически будет создана другая сессия.

## 7. Как начать отдельную новую сессию

Самый простой безопасный способ — открыть игру в новом приватном окне браузера.
Существующая сессия при этом остается в базе.

Для нового запуска в текущем профиле можно открыть инструменты разработчика
браузера, перейти в `Console` и выполнить:

```javascript
localStorage.removeItem("cubica-cards-money-trains-mock-session-id")
```

После обновления страницы Player Web создаст новую сессию. Команда удаляет
только локальную ссылку браузера и не стирает старую запись из PostgreSQL.

## 8. Диагностика

### База не запускается

Проверьте состояние и последние сообщения:

```bash
docker ps -a --filter name=cubica-cmt-postgres
docker logs --tail 100 cubica-cmt-postgres
```

Если Docker сообщает, что имя уже занято, контейнер уже создан. Используйте
`docker start cubica-cmt-postgres`, а не повторяйте `docker run`.

### Runtime API не готов

Проверьте отдельно сам процесс и его соединение с базой:

```bash
curl -fsS http://127.0.0.1:3001/health
curl -fsS http://127.0.0.1:3001/readiness
```

Первый запрос подтверждает, что процесс жив. Второй подтверждает, что доступно
постоянное хранилище. Если первый проходит, а второй нет, проверьте состояние
PostgreSQL и значение `DATABASE_URL` в терминале Runtime API.

### Игра не загружается

Проверьте доступность именно тестового пакета:

```bash
curl -fsS http://127.0.0.1:3001/games/cards-money-trains-mock/readiness
curl -fsS http://127.0.0.1:3001/games/cards-money-trains-mock/player-content
```

Если Runtime API отвечает, а браузер показывает ошибку, проверьте второй
терминал: Player Web должен быть запущен с
`RUNTIME_API_URL=http://127.0.0.1:3001`.

### Порты уже заняты

Для пробного запуска можно выбрать, например, `3101` для Runtime API и `3100`
для Player Web. Во всех командах согласованно замените порты:

```bash
export PORT=3101
# запуск Runtime API

RUNTIME_API_URL=http://127.0.0.1:3101 PORT=3100 \
NEXT_IGNORE_INCORRECT_LOCKFILE=1 \
npm run dev --workspace @cubica/player-web
```

Тогда адрес игры будет
`http://127.0.0.1:3100/?gameId=cards-money-trains-mock`.

### После перезапуска открылась новая партия

Проверьте следующие условия:

- используется тот же браузерный профиль;
- локальные данные сайта `127.0.0.1:3000` не очищались;
- запущен контейнер `cubica-cmt-postgres` с томом `cubica-cmt-pgdata`;
- Runtime API запущен с `SESSION_STORE=postgresql`, а не с временным
  `in-memory`.

## 9. Полное удаление тестовых данных

Следующие команды необратимо удаляют все локальные тестовые сессии из этого
контейнера. Выполняйте их только когда продолжение партий больше не нужно:

```bash
docker stop cubica-cmt-postgres
docker rm cubica-cmt-postgres
docker volume rm cubica-cmt-pgdata
```

После этого следующий запуск снова начинается с раздела 3.1.

## 10. Известные ограничения

- Постоянная mock-сессия содержит вымышленные данные и предназначена только
  для регрессии. Для продуктовой и визуальной проверки используется реальный
  предпросмотр раздела 3.4.
- Существующая партия восстанавливается на той же версии сервера. Точный
  многоверсионный реестр и архивная граница уже реализованы, но перед
  следующей сменой Mechanics точные исполняемые корпуса ещё нужно сохранять
  как долговечные frozen schema/checker/executor snapshots (`LEGACY-0072`).
  CMT сейчас закрепляет в том числе `cubica.core 1.4.3`,
  `cubica.random 1.1.0` и `cubica.graph 2.2.0`; предреестровые блокировки
  остаются archive-only, а не исполняются новым кодом.
- Технические события сохраняются, но полноценный пользовательский журнал
  ходов и выгрузка отложены как `LEGACY-0053`.
- Итоговый ИИ-анализ и учебная рефлексия отложены как `LEGACY-0054`. В будущем
  это будет отдельная производная от фактического журнала: она не изменит счет
  или состояние, не будет психологически оценивать участников и должна будет
  показывать, где факт, а где интерпретация.
- Обычный экран публикует 93 нетехнических действия и получает параметры
  настройки, обслуживания, строительства, движения, груза, состава и расчёта
  из текущего публичного состояния. Итоговый расчёт, два рейтинга и табличный
  денежный корректор реализованы и включены в новый локально опубликованный
  игровой модуль, но ждут полного ручного визуального прохода PM вместе с
  пространственными подсказками реальных областей (`LEGACY-0058`).
- Две методические паузы уже зависят от номера хода, сохраняются, переносятся и
  завершаются. Во время отчётности доступна сводка команд и отдельная финальная
  памятка. Официальный итоговый расчёт и ручное завершение готовы; будущий
  ИИ-разбор и полноценный журнал остаются отдельным отложенным объёмом.
- Партия после перезапуска продолжает с сохранённого игрового снимка; будущая
  случайность не является частью этого снимка. Технические проверки при
  необходимости используют только внутренний управляемый источник в процессе
  теста, а не профиль или данные сессии (`LEGACY-0067` закрыт).
- Исходники игрового интерфейса и опубликованный неизменяемый модуль
  синхронизированы. Перед сборкой свободный swap был безопасно восстановлен
  до 24%; процессы параллельной игры на портах `3200/3201` не
  останавливались.
- Построенные в ходе `N` объекты остаются закрыты весь `N+1` и автоматически
  открываются в начале `N+2`; независимое закрытие новостью при этом сохраняется.
- Сессия автоматически возобновляется только в том же браузерном профиле.
  Не очищайте данные сайта; безопасный способ повторного подключения после
  потери localStorage отложен как `LEGACY-0060`.

## 11. Автоматическая проверка реального содержимого

Эта проверка не снимает запрет публикации. Она создаёт временную
непубликационную копию нормативного пакета в `.tmp/`, открывает её через
обычный экран ведущего и после проверки удаляет. Сценарий доказывает два
реальных пути:

1. новость № 24, груз `1 → 9`, формирование состава, движение, выплата и тариф;
2. новость № 11, закрытие дороги `1 ↔ 9` и атомарный отказ движения без
   частичного изменения состояния.

Чтобы не пересекаться с другими локальными играми, используются порты
`3300/3301`. Сначала выполните безопасную проверку памяти:

```bash
skills/C_low-memory-host-operations/scripts/preflight.sh
```

Если проверка сообщает о другой сборке или недостатке памяти, дождитесь
освобождения ресурсов и не останавливайте неизвестный процесс. Затем
последовательно соберите только Player Web и запустите браузерный сценарий:

```bash
RUNTIME_API_URL=http://127.0.0.1:3301 \
PLAYER_WEB_URL=http://localhost:3300 \
npm run build --workspace @cubica/player-web

E2E_SERVER_MODE=prod \
E2E_LOW_RESOURCE=1 \
E2E_PLAYER_ONLY=1 \
E2E_RUNTIME_PORT=3301 \
E2E_PLAYER_PORT=3300 \
E2E_RUNTIME_URL=http://127.0.0.1:3301 \
npx playwright test \
  apps/player-web/e2e/cards-money-trains-real-operating-turn.spec.ts \
  --workers=1
```

Тест сам запускает и останавливает принадлежащие ему процессы. После него
порты `3300/3301` должны быть свободны. Проверка восстанавливает состояние
после перезагрузки страницы, но не заменяет отдельный тест восстановления
рабочей PostgreSQL-сессии после перезапуска сервера.
