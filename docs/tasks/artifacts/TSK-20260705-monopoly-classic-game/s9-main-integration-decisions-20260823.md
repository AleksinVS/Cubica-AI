# Рабочие решения интеграции S9 с актуальным `main`

Дата: 2026-08-23. Статус: автономные неархитектурные решения, оставленные
явными для последующего пересмотра. Принятые границы ADR-059 и ADR-060 ими не
изменяются.

## Единая настройка локальной партии

- Экран подготовки выбирает одновременно общее число участников и число мест
  ИИ. Два последовательных экрана не вводятся: оба значения образуют один
  запрос создания сессии, а идентичности мест по-прежнему назначает сервер.
- Для игры с фиксированным числом участников и без мест ИИ сессия создаётся
  автоматически. Гибкий диапазон участников или объявленные места ИИ требуют
  явного подтверждения.
- Число мест ИИ ограничивается меньшим из выбранного числа участников и
  объявленного `agentSeats.max`. Объявленный максимум относится ко всему
  поддерживаемому диапазону партии и не обязан быть меньше каждого выбранного
  локального размера.

## Восстановление и сброс

- Сброс существующей локальной партии сохраняет её фактическое общее число
  участников и число мест ИИ. Альтернатива — повторно открывать подготовку —
  меняла бы смысл уже принятого сброса и могла случайно изменить состав партии.
- Недоступная сохранённая сессия (`401`/`404`) заменяется партией минимального
  размера только с людьми. Старый состав не считается доверенными данными без
  действующего удостоверения сессии.
- Portal launch и editor preview не показывают локальную подготовку: первый уже
  привязан к портальному запуску, второй уже владеет конкретной preview-сессией.

## Что можно пересмотреть

- Продуктовый текст и компоновку единого экрана подготовки после визуальной
  приёмки.
- Нужно ли при явном выборе «только люди» опускать `agentSeatCount: 0` в HTTP
  теле. Сейчас ноль передаётся явно; канонический контракт считает отсутствие
  поля эквивалентным нулю.
- Нужно ли предлагать повторную настройку при обычном сбросе. Текущий выбор в
  пользу сохранения состава минимизирует неожиданное изменение партии.
