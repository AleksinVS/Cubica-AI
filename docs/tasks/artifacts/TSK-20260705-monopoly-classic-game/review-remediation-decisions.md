# Спорные решения исправления находок ревью

Этот файл фиксирует автономные исполнительские решения внутри уже принятых
границ ADR-059 и ADR-103. Он не запускает S9, сетевой lifecycle или
ИИ-интерпретацию журнала.

## DEC-REVIEW-001: необязательный participantCount

- **Решение:** публичное создание сессии принимает необязательное целое
  `participantCount`; отсутствие означает `config.players.min`.
- **Почему:** старые клиенты сохраняют поведение, а игры с диапазоном получают
  настоящий пользовательский путь без второго create endpoint.
- **Пересмотреть, если:** все поддерживаемые клиенты перейдут на явный выбор и
  продукт решит запретить неявный минимум новой major-версией контракта.

## DEC-REVIEW-002: диапазон проверяет runtime по манифесту

- **Решение:** OpenAPI проверяет форму и положительное целое, а runtime после
  загрузки закрепляемого game bundle проверяет динамический диапазон
  `config.players.min..max`.
- **Почему:** OpenAPI не знает диапазон конкретной версии игры; дублирование
  этих чисел в Player или общей схеме создало бы второй источник истины.
- **Пересмотреть, если:** появится отдельный schema-backed launch profile,
  который сужает диапазон манифеста по режиму партии.

## DEC-REVIEW-003: выбор только перед первой свежей локальной сессией

- **Решение:** общий Player показывает подготовку только для новой локальной
  сессии игры с `min < max`. Фиксированное число, resume, portal launch и editor
  preview сохраняют автоматический запуск; reset сохраняет число текущих мест.
- **Почему:** эти пути уже имеют созданную или служебно управляемую сессию, а
  повторный выбор перед resume изменил бы смысл восстановления.
- **Пересмотреть, если:** продукту понадобится отдельное общее лобби, которое
  управляет не только числом мест, но и их типами и подключением.

## DEC-REVIEW-004: ранний отказ журнала без усечения

- **Решение:** PostgreSQL читает публичные события небольшими keyset-страницами
  в одной repeatable-read транзакции и прекращает чтение сразу при точном
  превышении лимита JSON; документ по-прежнему не усекается.
- **Почему:** это устраняет многогигабайтную материализацию до 413 и сохраняет
  согласованную границу журнала без нового формата доставки.
- **Пересмотреть, если:** реальные журналы приблизятся к лимиту; тогда нужен
  отдельно согласованный потоковый или постраничный публичный протокол.
