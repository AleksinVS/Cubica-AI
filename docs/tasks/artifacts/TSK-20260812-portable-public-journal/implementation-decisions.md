# Спорные исполнительские решения переносимого журнала

Документ хранит решения, которые не меняют принятую границу ADR-103, но могут
потребовать пересмотра после реального использования.

## DEC-JOURNAL-001: первый переносимый формат — JSON

- **Решение:** версия `1.0.0` поставляется только как JSON.
- **Почему:** только JSON сохраняет вложенные типизированные `summary`, `data` и
  `metricChanges` без второго преобразования и потерь.
- **Пересмотреть, если:** ведущим понадобится массовая табличная обработка; CSV
  тогда строится как отдельное производное представление, а не заменяет JSON.

## DEC-JOURNAL-002: минимальная безопасная оболочка события

- **Решение:** экспортируются `eventId`, `sequence`, `eventType`, `occurredAt`,
  `summary`, `data`, `metricChanges`; `actionId`, `actorId`, `principalId`,
  `commandId` и `receiptId` не экспортируются автоматически.
- **Почему:** только полезная нагрузка публичного события объявлена игрой как
  публичная. Идентичность участника при необходимости должна быть явным полем
  типизированного `data`, а не неявной утечкой внутренней оболочки.
- **Пересмотреть, если:** появится общий schema-backed публичный actor reference
  с отдельным решением о приватности и псевдонимизации.

## DEC-JOURNAL-003: живой журнал доступен всем principal сессии

- **Решение:** любой аутентифицированный участник живой сессии может выгрузить
  события с аудиторией `public`; архив сохраняет существующее ограничение роли
  ведущего.
- **Почему:** live-доступ не шире уже заявленной аудитории события, а архив
  относится к отдельной защищённой audit boundary.
- **Пересмотреть, если:** появятся сетевые сессии с публичными событиями,
  запрещёнными к самостоятельному сохранению участником, или отдельное право
  `journal:export`.

## DEC-JOURNAL-004: полный ответ с отказом вместо усечения

- **Решение:** схема допускает не более 65 536 публичных записей, runtime также
  применяет ограничение сериализованного ответа; превышение завершает запрос
  явной ошибкой и не выдаёт неполный файл.
- **Почему:** молчаливое усечение делает документ недостоверным. Лимит защищает
  память общего runtime до появления потоковой/постраничной доставки.
- **Пересмотреть, если:** реальные сессии приближаются к лимиту или журнал
  становится длительным многодневным потоком; предпочтение — совместимая
  постраничная доставка с проверяемой сборкой того же документа.

## DEC-JOURNAL-005: файл не содержит времени экспорта

- **Решение:** документ содержит авторитетные `sessionCreatedAt`, необязательный
  `archivedAt` и времена событий, но не добавляет текущее `exportedAt`.
- **Почему:** два чтения одной и той же границы остаются одинаковыми и пригодны
  для побайтовой проверки; время сохранения файла является метаданными клиента.
- **Пересмотреть, если:** внешний документооборот потребует подписанный конверт
  доставки; он должен оборачивать журнал, а не менять фактическое содержимое.

## DEC-JOURNAL-006: предел применяется внутри хранилища

- **Решение:** Runtime передаёт хранилищу предел 65 537 публичных событий —
  лимит формата плюс одну запись для доказательства переполнения. PostgreSQL
  внутри одной `repeatable read`-транзакции читает только нужные метаданные и
  события небольшими keyset-страницами; после каждой записи проверяются предел
  количества и точный размер будущего JSON. Превышение останавливает чтение с
  413 до материализации всей истории.
- **Почему:** проверка после загрузки всей истории формально ограничивала файл,
  но не расход памяти сервера. Инкрементальная проверка сохраняет отказ без
  усечения и не допускает многогигабайтную промежуточную выборку.
- **Пересмотреть, если:** появится потоковая или постраничная выдача с
  проверяемым протоколом полноты; она должна сохранять ту же границу событий и
  правила доступа.
