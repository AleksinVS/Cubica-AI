## Why

Ведущему нужен не свободный пересказ партии, а проверяемый черновик итогового
разбора: наблюдаемые факты должны ссылаться на подтверждённые события, выводы —
быть явно отделены от фактов, а вопросы — следовать принятой методике CMT.
Черновик помогает провести финальную рефлексию, но не меняет счёт, состояние
партии и решения ведущего.

Эта задача продолжает реализованный переносимый журнал и закрывает
`LEGACY-0054`. Архитектурная граница, поставщик и профиль приватности приняты
PM 2026-09-04 и зафиксированы в ADR-104.

## Accepted Boundaries

- ADR-103 оставляет переносимый журнал неизменяемым фактическим документом.
  ИИ-разбор обязан быть отдельным версионированным производным артефактом.
- CMT остаётся deterministic-игрой. Итоговый разбор не является Agent Turn,
  не выбирает Game Intent и не переводит игру в `hybrid`.
- Вход строится только из точной версии подтверждённого публичного журнала и
  опубликованной методики игры. Защищённый аудит, секретное состояние и
  свободные персональные заметки не передаются модели.
- Результат всегда имеет статус черновика до подтверждения ведущим. Даже
  подтверждённый документ не становится источником истины игровых фактов.
- Психологические оценки участников, скрытые профили и автоматические решения
  о людях запрещены.

## Architecture Decision Required

Решение принято PM 2026-09-04 и зафиксировано как Accepted ADR-104. Ниже
сохранён согласованный пакет решения, а не открытый вопрос.

Нужно утвердить одну общую read-only границу «производный ИИ-артефакт сессии».
Рекомендация:

1. Отдельный schema-first контракт содержит версию, точную границу
   `throughEventSequence`, хэш входного журнала, версию методики, версию промта,
   поставщика, точный идентификатор модели и три раздельных блока: факты со
   ссылками на `eventId`, интерпретации и вопросы ведущему.
2. Генерация и подтверждение доступны только аутентифицированному ведущему.
   Подтверждение закрепляет точный хэш результата; редактирование в первой
   версии заменяется новой генерацией, чтобы не вводить редактор и историю
   свободного текста.
3. Запрос, структурированный ответ, происхождение, расход токенов, ошибки и
   решение ведущего сохраняются в отдельном ограниченном PostgreSQL-хранилище.
   Session state, event ledger и command receipt не используются как второе
   хранилище ИИ-артефакта.
4. Поставщик вызывается сервером в foreground-режиме без инструментов,
   встроенного поиска и provider-side conversation state. Ответ обязан пройти
   строгую JSON Schema и смысловую проверку ссылок на события.
5. Первый adapter — OpenAI Responses API с `store: false`, закреплённым снимком
   модели и версионированным промтом. Production-вызов разрешён только в
   одобренном проекте хранения данных; без него контур fail closed. Конкретный
   снимок выбирается по зафиксированному replay/eval набору до включения
   настоящего трафика.
6. Вход ИИ имеет отдельный меньший лимит, чем 32-МиБ переносимый журнал.
   Нормативная полная партия CMT должна проходить этот лимит; превышение даёт
   явный отказ без усечения. Многошаговое свёртывание не вводится до измеримого
   примера, который не помещается в один запрос.

Альтернативы:

- расширить существующий Agent Turn — отклоняется в предложении, потому что он
  выбирает изменяющее намерение внутри command transaction, а разбор только
  читает подтверждённую историю;
- сохранить результат только в браузере — теряет серверное происхождение,
  подтверждение и аудит;
- начать с mock-only — безопасно для контракта и replay, но не даёт ведущему
  реального продуктового результата и не закрывает долг;
- сразу построить универсальный многошаговый конвейер свёртывания — преждевременно
  до измерения размера нормативной CMT-партии.

Одобрение PM должно подтвердить саму границу, допустимого поставщика и профиль
хранения данных. Выбор внутренних имён, таблиц, маршрутов и исполнителей после
этого остаётся исполнительской деталью.

## Scope

- schema-backed контракт входа, результата, происхождения и подтверждения;
- отдельная read-only служба и долговечное ограниченное хранилище артефактов;
- серверный provider adapter с таймаутом, классификацией отказов, квотой и
  отсутствием автоматического повтора после неизвестного исхода;
- game-owned версия методики CMT и правила проверки ссылок на события;
- интерфейс ведущего: создать черновик, увидеть факты/выводы/вопросы,
  подтвердить точный вариант либо запросить новый;
- replay/eval набор с настоящим CMT-журналом и отрицательными сценариями;
- закрытие `LEGACY-0054` только после настоящего provider proof и ручной
  продуктовой приёмки ведущим.

## Non-Goals

- изменение игрового состояния, счёта, рейтинга или доступности действий;
- показ разбора игрокам без решения ведущего;
- психологическая оценка, кадровые рекомендации и сохранение персональных
  заметок;
- чат с моделью, инструменты, web/file search, векторная база и долговременная
  provider conversation;
- общий конструктор промтов и поддержка нескольких поставщиков в первой версии;
- молчаливое усечение большого журнала или fallback на другую модель.

## Plan

1. Sol high фиксирует принятый вариант в ADR и синхронизирует обзор архитектуры.
2. Sol high проектирует schema-first контракт, хранение, доступ, идемпотентность,
   квоты, отказоустойчивость и тестовую матрицу; совместимость доказывается
   нейтральной фикстурой и CMT.
3. Sol high реализует критическую серверную границу и provider adapter. Ни один
   внешний вызов не выполняется до отдельного preflight разрешённого проекта и
   credential.
4. Luna high реализует ограниченный CMT-профиль методики и интерфейс ведущего
   по зафиксированным контрактам. После тестов Luna xhigh выполняет read-only
   критику diff; дефекты исправляет Luna, затем Sol high принимает результат.
5. Luna high реализует replay/eval runner по разработанной Sol high матрице.
   После сфокусированных тестов Luna xhigh критикует фактические ложные ссылки,
   смешение фактов с интерпретациями и отрицательные пути; исправление и
   повторные тесты проходят до Sol high приёмки.
6. Основной Sol high агент проверяет интегрированный diff, лично проводит
   итоговую браузерную UI/UX-приёмку, настоящий ограниченный provider proof и
   ручную приёмку ведущего и только затем закрывает долг и обновляет
   CMT/NEXT_STEPS. Luna-критика остаётся предварительной и не заменяет этот
   вердикт.

Проверка на упрощение: отдельный сервис, очередь заданий, универсальный registry
поставщиков, редактор текста и многошаговое свёртывание не создаются. Один
синхронный ограниченный запрос и одна таблица производных артефактов достаточны,
пока измерения не докажут обратное.

## Acceptance

- каждый факт содержит хотя бы одну существующую ссылку на событие текущего
  закреплённого журнала; неизвестная ссылка отклоняет весь результат;
- интерпретации и вопросы визуально и контрактно отделены от фактов;
- ни один запрос или ответ не меняет session state/version/event sequence;
- только ведущий создаёт, читает и подтверждает ИИ-артефакт;
- повтор той же команды не создаёт второй внешний вызов или второй артефакт;
- точные model/prompt/provider/input/output hashes и usage сохранены, секреты и
  защищённый аудит отсутствуют;
- timeout, 429, неизвестный 5xx/transport outcome, malformed JSON, schema error,
  ложная ссылка и превышение лимита fail closed без автоматического fallback;
- нормативная полная CMT-партия помещается в утверждённый входной бюджет;
- независимый replay/eval и ручная оценка ведущего проходят до включения.
- итоговый экран проверен основным Sol-high агентом в браузере: понятна разница
  фактов и интерпретаций, состояние черновика/подтверждения очевидно, ошибки не
  маскируют фактический журнал, клавиатурный путь не уступает мыши.

## Risks

- публичный журнал может содержать свободные названия команд; до внешнего
  вызова нужен утверждённый профиль приватности и явное пользовательское
  объяснение передачи данных;
- текущий Agent Runtime имеет только mock adapter, поэтому provider boundary не
  считается реализованной повторным использованием существующего Agent Turn;
- 32-МиБ лимит выгрузки намного шире разумного одиночного LLM-входа; отдельный
  меньший предел должен быть измерен на полной CMT-партии;
- качество нельзя доказать только schema validation: нужны зафиксированные
  примеры, ложные выводы и ручной rubric ведущего;
- непредсказуемая стоимость ограничивается одним запросом, token cap и явной
  квотой; изменение этого профиля требует повторной оценки стоимости.

## Plan Amendments

### 2026-09-18 — перейти на `glm-5.3-flash`

После подтверждения доступа текущим ключом (один прямой минимальный запрос,
HTTP 200 и `model=glm-5.3-flash`) PM явно поручил изменить модель в настройках.
Тестовый контур закреплён за `glm-5.3-flash`; поправка от 2026-09-15 о
сохранении `glm-4.7` заменена этим решением. Точная проверка поля `model`,
синтетические фикстуры и изоляция от рабочего OpenAI runtime остаются в силе.
Фактический доступ не считается подтверждением изменения договорных условий
старой ревизии Coding Plan. Эта смена настроек не выдаёт допуска качества и
не требует нового сетевого proof.

### 2026-09-15 — сохранить `glm-4.7`

PM подтвердил, что текущая подписка Coding Plan предоставляет только
`glm-4.7`, и отклонил переход синтетического proof на `glm-5.3`. Точная модель
остаётся закреплена как `glm-4.7`; принимать любой иной provider-reported model
id запрещено. Следующий диагностический шаг должен установить безопасное
эквивалентное имя или documented alias ответа Coding Plan без ослабления model
identity gate и без перехода на general API billing.
Это ограничение модели заменено явным решением PM от 2026-09-18 выше.

### 2026-09-11 — Coding Plan URL для ручного proof из Codex

PM явно поручил повторить синтетический proof с `ZAI_BASE_URL`. Официальная
документация Z.AI относит Codex к поддерживаемым Coding Plan-инструментам и
указывает `https://api.z.ai/api/coding/paas/v4` для OpenAI Chat Completions.
Решение ограничено ручным proof внутри Codex: base URL проверяется по точному

### 2026-09-05 — Z.AI как основной поставщик синтетической проверки

PM явно поручил использовать доступный `ZAI_API_KEY` как основной credential
тестового контура. Из-за отсутствия документированного Responses API, строгой
server-side JSON Schema и однозначного отключения automatic context caching
граница сужена до одного ручного вызова `glm-4.7` на закреплённой синтетической
CMT-фикстуре. Адаптер не подключается к runtime, не меняет публичный контракт
артефакта и не заменяет production OpenAI proof.
