проверяет фактический результат каждого критического блока.

Не добавляются библиотека позиционирования, новый текстовый редактор, YAML-
парсер для произвольных преобразований или инфраструктура фоновых задач.

## Execution

- Причина перекрытия: prompt самостоятельно переходит налево для обхода рамки,
  список всегда открывается `x=max(8,cursor.x-184)` и о переходе не знает.
  Подъём z-index лишь поменял бы перекрываемый объект, поэтому исправляется
  согласование геометрии.
- CSS браузера сохраняет переносы и моноширинный шрифт (12/18 px, pre-wrap).
  Причина плоского YAML — отсутствие group в описаниях Antarctica и вывод всех
  свойств одним уровнем. Генератор использует смысловые секции по существующему
  facet с приоритетом явно заданной группы. Несколько полей одной группы не
  создают повторные YAML-ключи. Один скаляр остаётся компактным.
- Настоящие переводы строк внутри значений пока сохраняются как JSON-escaped
  scalar: текущая точная обратная запись основана на строковой карте. Изменение
  самого значения для форматирования недопустимо; длинные строки переносятся
  визуально. Переход к block scalar потребовал бы отдельного изменения карты
  и интерпретатора; для восстановления секций это не требуется.
- Замер неизменённой Antarctica на изолированной копии: compile 1337/255/213 мс,
  validateAndBundleProjectPlugins 10507/9687/10093 мс в трёх последовательных
  вызовах. Во всех сборках compiler cache: 3 попадания, 0 промахов. Это локальный
  диагностический замер, не статистический p95. Скрипт и полный лог:
  `.tmp/editor-feedback-20260921/performance.test.ts`, `performance.log`.
- Чтение кода подтверждает: prepare собирает кандидата и плагин; confirm снова
  компилирует; обновление preview снова компилирует и проверяет плагин. Прямые
  жесты проходят compile до записи и затем отдельную подготовку preview.
  Браузерный замер подготовки preview на рабочем стенде — 11,8 секунды;
  это не время отдельной правки. Замеры не включают внешнего агента.
- [ADR-109](../../architecture/adrs/109-responsive-editor-draft-preview.md)
  описывает три варианта, рекомендует временные значения в том же renderer,
  проверки по приоритетам и очередь без потери последующих правок. Приоритеты
  определяются конвейером, а не прототипами.

### Реализация принятого ускорения (2026-09-21)

- Серверный блок — Sol high: кэш полного отпечатка плагинов с проверкой
  артефактов и объединением одновременных проверок; ограниченный перенос точно
  проверенного кандидата prepare → confirm → preview. Кэш только в памяти,
  отсутствие записи означает обычную проверку. Коммит `aa227b1`.
- Player и декларативный контракт — Sol high: временные значения текста и
  геометрии отображаются существующим React renderer; проверяются владелец,
  ревизия, сцена, номер сообщения и подтверждённая пауза. Логика, журнал и
  авторские файлы не меняются. Коммит `26cc108`.
- Очередь — Sol high; интеграция и приёмка — основной агент. Ответ A не стирает
  B; отказ A сохраняет независимую B, зависимая остаётся конфликтным черновиком.
  Неоднозначный ответ оставляет точный запрос для повтора с тем же ID.
  При неудаче обновления после успешной записи сохраняется видимая правка и
  предлагается повторить обновление без второй записи.
- Полное независимое ревью проверило серверный кэш, границу player и клиентские
  переходы. Исправлены устаревший кандидат после новой неудачной подготовки,
  повтор известной операции после следующей записи, неполный отпечаток
  компилятора, очистка слоя при отмене, обработка позднего ответа другой сессии
  и проверка локальных source guards перед временным отображением.
- Браузер выявил длинный ID, унаследованный от пути сущности: он превышал
  ограничение wire-контракта и мешал показу YAML-кандидата. Теперь пользовательская
  операция получает отдельный короткий UUID; повтор транспорта сохраняет его.
- Проверка упрощения: нет новой библиотеки состояния, фонового брокера, базы
  данных, графа приоритетов прототипов или совместимости тестовых сессий.
  Точный консервативный конфликт предпочтён автоматическому угадыванию цели.
  Неподдержанные визуальные эффекты используют прежний проверяемый путь.
  Удалены неиспользуемое хранение готовых патчей очереди, предположения о
  неоговорённых идентификаторах и дублирующее уведомление во время проверки.
  Стоимость полного хэширования входов отдельно не измерена; кэш не объявляется
  гарантией мгновенного серверного подтверждения.
- После полной смены исполняемой версии готовность означает подключение нового
  iframe: совпали ревизия, сообщения о видимых элементах и игровая сессия.
  Пока этого нет, очередь не считается согласованной с player. Ожидание
  ограничено 30 секундами и отменяется при смене источников/игры/предпросмотра.
  Эта исполнительская деталь закрывает обнаруженную E2E гонку выбора этапа.
- Негативный браузерный сценарий выявил потерю textBinding при показе временного
  текста: renderer строил служебные атрибуты из уже заменённых props.
  Источник служебных атрибутов отделён от отображаемого компонента; ссылка на
  содержимое сохраняется для всех экземпляров. Регрессия проверяет две замены
  вычисляемого текста и очистку слоя. Нажатия в игре во время подтверждения
  команды паузы/продолжения блокируются до ответа.

## Acceptance

- Окно и исчезающий список не перекрываются после открытия, resize и drag.
  При достаточном месте они по разные стороны курсора. Невозможность строгой
  противоположности в самом углу экрана разрешается видимым непересекающимся
  размещением, а не обрезкой списка.
- YAML содержит секции и отступы; изменение значения по-прежнему попадает
  в точный авторский источник. Нет потери текста, скрытых привязок в UI или
  трёх отдельных полей вместо одного текста.
- В предложении разделены показ/подтверждение, критические/второстепенные
  проверки, поздний ответ, отказ ранней правки, конфликт зависимостей и агент.
- Рабочие службы доступны; ни пользовательская история, ни прохождение
  не потеряны. Результаты проверок и ограничения указаны честно.
