## Why

Текущие правила уже требуют выбирать проверки по размеру и риску изменения,
но фактический CI повторяет часть проверок, повторно собирает Player Web и
запускает дорогой браузерный контур до результата дешёвых шлюзов. Нужно
сократить повторную работу и объём журналов для агентов, сохранив действующие
контрактные, архитектурные и пользовательские гарантии.

## Scope

В работу входят:

- непересекающиеся CI-задания с сохранением действующих обязательных статусов;
- запуск production E2E только после успешных дешёвых шлюзов;
- отмена устаревших прогонов одного pull request;
- локальные команды для затронутых, упавших, профилируемых и smoke-проверок;
- консервативный селектор затронутых проверок с полным резервным набором для
  неизвестных и критичных изменений;
- профильные Player, Editor и Portal E2E-сценарии;
- диагностическая трассировка и артефакты только после ошибки;
- измерение длительности стадий и компактный формат передачи результата;
- синхронизация правил агентов и архитектурной документации.

Не входят:

- включение защиты ветки `main`;
- отдельный ночной прогон;
- параллельные Next.js-сборки;
- миграция всех тестов на один test runner;
- кэширование `node_modules`, `.next`, тестовых баз или контейнеров;
- автоматический карантин нестабильных contract/security/authorization тестов.

## Plan

1. Зафиксировать утверждённую ступенчатую политику в существующем решении о
   тестовой архитектуре и общей архитектуре проекта.
2. Разделить корневые команды на полный локальный контур и непересекающийся
   CI-контур без потери совокупного покрытия.
3. Добавить проверяемый селектор затронутых областей и компактное
   профилирование команд.
4. Разделить E2E по профилям, сделать первый прогон дешёвым, а диагностический
   повтор — ограниченным упавшими тестами.
5. Перестроить CI: дешёвые шлюзы раньше E2E, отмена устаревших PR-прогонов,
   краткая сводка длительности и failure-only артефакты.
6. Обновить правила агентов и выполнить сфокусированную проверку конфигурации,
   селектора, документации и изменённых скриптов.

## Execution

- Архитектура и итоговая приёмка: основной агент, Sol.
- CI, E2E и селектор затронутых тестов: сложный разработчик, Sol high, потому
  что ошибка выбора может молча пропустить обязательную проверку.
- Документация и правила агентов: механический разработчик, Terra low, в
  пределах уже утверждённого решения.
- Комплексная read-only проверка: QA reviewer, Terra low; пакет объединяет
  несколько простых команд и инспекций, но итоговую приёмку выполняет основной
  агент.

Заключительное упрощение: сохраняются текущие Node Test, Vitest и Playwright;
новый сервис, общий test runner, графовая система сборки и ночной оркестратор
не создаются. Селектор строится как небольшой fail-closed policy script:
неизвестность всегда расширяет, а не сужает набор.

## Acceptance

- `verify:canonical` остаётся полной локальной точкой проверки.
- CI не повторяет `verify:legacy`, `verify:manifest-authoring` и Player Web
  build внутри одного прогона.
- E2E не стартует после падения любого обязательного дешёвого шлюза.
- Устаревший прогон одного pull request отменяется; push в `main` не отменяется
  этим правилом.
- Есть исполняемые команды affected, failed, profile и E2E smoke.
- Неизвестные, общие и критичные изменения выбирают полный резервный набор.
- Первый E2E-прогон не пишет тяжёлое видео/trace для успешных тестов;
  диагностический повтор ограничен упавшими тестами.
- Полные журналы и отчёты остаются в `.tmp/` локально либо публикуются в CI
  только при ошибке с ограниченным сроком хранения.
- Документация явно сохраняет решения PM: защита `main` не включается, ночной
  контур не создаётся.

## Validation

- тесты селектора затронутых областей;
- проверка синтаксиса workflow и package scripts;
- `npx playwright test --list` для новых E2E-профилей без запуска сервисов;
- сфокусированные проверки новых вспомогательных скриптов;
- `npm run verify:legacy`;
- `git diff --check`;
- полный production E2E и полный `verify:canonical` не запускаются локально,
  если их покрытие не требуется остаточным риском и preflight маломощного хоста
  не разрешает дорогой прогон.
