## Принятые границы

PM принял постепенное подключение наброска к игре и уточнил общий масштаб платформы.
Правила остаются в game authoring/Mechanics; код владеет реализацией представления,
объявленные свойства экземпляров — авторскими переопределениями. YAML остаётся
временной семантической проекцией. Известные однозначные свойства идут через
детерминированный путь, новый смысл и код — через проверяемый результат агента.
Отрисовщик сообщает семантическую идентичность, выбор и доступные операции;
экранная рамка не считается универсальным способом преобразования 3D-объекта.
Миграция не означает двустороннюю синхронизацию двух исходников UI.
Существующие границы серверных команд, подтверждения изменений и паузы сохраняются.

Публикуемое владение не передаёт и не расширяет отдельную активную границу
`TSK-20260831-project-review-remediation` F-004/F-010. Новый контур использует её
существующие публичные операции. При обнаружении требуемой несовместимой правки
координатор сначала согласует пересечение с владельцем; параллельная перезапись запрещена.

## Миграция и критерии завершения

1. Установить существующие правила и воспроизводимые примеры; для пробелов записать
   авторское намерение и обозначить демонстрационность, не создавать вторую игровую логику.
2. Выбрать целевую платформу и области UI. Агент предлагает минимальные завершённые
   этапы по зависимостям поведения, ограничениям клиента и проверяемым примерам.
3. Переносить область целиком с её действиями, состояниями и редактируемыми свойствами.
   До принятия целевой реализации текущая рабочая версия остаётся доступной.
4. Проверить на тех же реальных примерах; изменение правил/источников делает старое
   доказательство устаревшим. Демонстрация не подтверждает серверную корректность.
5. Переключить принятую область на целевую реализацию. Старый набросок — справочный
   эталон. Новые эксперименты ответвляются от текущей реализации.

Минимальная приёмка: один нейтральный пример общей возможности; CMT редактируется
через существующие выбор/промт/YAML; одна область проходит путь от наброска к реальной
игре с положительным и запрещённым действием; пользователь видит, где макет, а где
настоящая сессия. 3D учитывается контрактом возможностей; полноценный 3D-движок,
универсальная трансляция HTML в любой движок и полная переработка CMT не входят.

Упрощения: один редактор, существующие авторские файлы и очередь изменений,
существующие игровой runtime и каналы ассетов; без универсального языка UI,
двусторонней синхронизации, новой базы снимков, брокера задач или отдельного
сервиса миграций. Точная декомпозиция B2–B5 уточняется после B0/B1 по коду без
расширения этих границ.
