## Резюме

Проект в хорошем инженерном состоянии. Ключевые архитектурные инварианты — чистота
платформы от игрового кода, единый транзакционный путь Game Intent → Mechanics IR,
недоверие клиентскому `playerId`, генерация TS-контрактов из JSON Schema — **реально
соблюдаются**, что подтверждено целевыми проверками, а не только чтением документации.
Защитное программирование в `runtime-api` (path traversal, SQL-инъекции, идемпотентность,
блокировки, лимиты тел запросов) выполнено на высоком уровне. Система документированного
долга работает: почти все найденные разрывы с целевой архитектурой уже зафиксированы
кодами `LEGACY-*`.

Главные проблемы сосредоточены в четырёх местах:

1. **Портал: сломанный контроль доступа** (критично). `updateOrderStatus` меняет статус
   любого заказа без проверки владельца и подписи; `generatePaymentLink` строит
   платёжную ссылку по чужому заказу. Контур помечен как draft, но код доступен в
   репозитории для тестового VPS-запуска (активная задача TSK-20260518-portal-…).
2. **Дыры в самих контрольных механизмах**. `validate-legacy.js` не сверяет статус
   `removed`-записей с секцией реестра заглушек — из-за этого уже существует реальное
   противоречие LEGACY-0036 (в `debt-log.csv` — `removed`, в `stubs-register.md` —
   `active` с другим содержанием). Редакторский контур (~60 тыс. строк editor-web +
   editor-engine) не проверяется ни CI, ни даже локальным `verify:canonical`.
   Компилятор манифестов пишет итоговые `game.manifest.json` неатомарно.
3. **Клиентские поверхности доверия**. Поле `integrity` бандлов плагинов объявлено в
   контракте, но не проверяется при `import()`; предпросмотр редактора при отсутствии
   `editorOrigin` шлёт снимок состояния сессии `postMessage`-ом с target origin `"*"`;
   `richTextComponent` вставляет HTML из манифеста без санитизации (AI-путь при этом
   защищён — асимметрия).
4. **Расхождение автозагружаемых правил**. `CLAUDE.md` (загружается автоматически)
   отстал от `AGENTS.md` по нумерации и содержанию: правила о масштабе проверок (п.14),
   интеграции веток (п.15), синхронизации ADR (§2.2) и актуальная формулировка platform
   purity до части агентов не доходят.

Сводка находок: **3 критично, ~25 важно, ~35 желательно** (полный перечень по разделам).
Также подтверждён прогресс с ревью 2026-06-27: баг инверсии JSON Patch исправлен и
покрыт тестом, editor-долг заведён в `debt-log.csv`, `editor-engine/index.ts` разбит,
хардкод Antarctica в рендерере устранён (остался только задокументированный CSS-долг
LEGACY-0076). Единственный регресс: компонент-гигант редактора «переехал» в
`use-editor-workspace.ts` (5021 строка, ~80 `useState`) и не переоткрыт как долг.

## 5. Код: services/runtime-api

~20 тыс. строк исходников + ~14 тыс. строк тестов (371 сценарий). Безопасность горячего
пути проверена целево и дыр не нашла: многослойная защита от path traversal (включая
`realpath`-containment от symlink), параметризованный SQL, `FOR UPDATE NOWAIT` → 423,
квитанции `commandId` с отказом при переиспользовании с другим содержимым, лимит тела
2 МБ до парсинга, бюджеты Mechanics почти на каждом операторе.

Главные находки — три прокола именно в системе бюджетов на геометрическом пути:

| Код | Серьёзность | Суть |
|---|---|---|
| RT-01 | важно | `graph.shortestPath`: BFS через `Array.shift()` — O(V²) вместо O(V+E), сам обход не заряжается в бюджет (`domainOperations.ts:548-559`). Оркестратор дополнительно подтвердил: построение списков смежности через spread-копирование массива на каждое ребро добавляет ещё один квадратичный вклад. Автор манифеста получает скрытую квадратичную стоимость в рамках разрешённых лимитов. |
| RT-02 | важно | `graph.edge.position.inspect`: наивная O(n²) проверка простоты полигона на каждый вызов без кэша (геометрия статична всю сессию), бюджет заряжается **после** выполнения работы. На реальной карте (78 тыс. вершин упомянуты в комментариях) — сотни миллионов операций до того, как бюджет узнает. |
| RT-03 | желательно | Причина RT-01/02: геометрические примитивы реализованы трижды (`graphGeometry.ts`, `regionRoadGeometry.ts`, `polygonTriangulation.ts`) с разной производительностью; оптимизирована только одна копия. Вынести в общий модуль. |
| RT-04 | желательно | `createRuntimeActionRegistry` пересобирает Map действий на каждый dispatch (минимум дважды), без `WeakMap`-кэша, который уже применяется в соседних модулях. |
| RT-05 | желательно | Кэш AJV-валидаторов предпросмотра дороги индексирован по идентичности объекта схемы, а схема пересоздаётся литералом на каждый запрос — кэш никогда не срабатывает. |
| RT-06 | желательно | Лимиты частоты команд/AI-бюджет — только в памяти процесса (задокументировано в коде, но не в debt-log); при горизонтальном масштабировании обходится. Завести LEGACY-запись. |
| RT-07 | желательно | Ни один тест не создаёт настоящую параллельную гонку (`Promise.all` двух команд на одну сессию) — сериализация блокировкой не доказана тестом. |
| RT-08 | желательно | Шесть модулей с нетривиальной логикой (systemScheduler, actionRegistry, commandTransactionValidation, agentRuntimeReadiness и др.) покрыты только косвенно интеграционным файлом на 2090 строк. |
| RT-09 | желательно | Единственный `Math.random()` в проекте — `agentRuntime.ts:848` (turnId); заменить на `randomUUID()` для соответствия задекларированному принципу единственного источника случайности. |
| RT-10..13 | желательно | Устаревший комментарий «модуль нигде не используется» в `polygonTriangulation.ts`; вытеснение кэша карт по порядку вставки вместо LRU; неограниченный `bundleCache` в `ContentService` (в отличие от соседнего ограниченного `VerifiedBundleCache`); предпросмотр дороги считает тяжёлую геометрию вне бюджетов Mechanics. |
