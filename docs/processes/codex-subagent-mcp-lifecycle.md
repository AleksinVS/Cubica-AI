# Context7 и жизненный цикл MCP субагентов Codex

Эта инструкция уменьшает расход памяти на общем рабочем хосте и сохраняет
изоляцию инструментов. Context7 подключается как общий удалённый сервис, а
MCP с изменяемым состоянием, прежде всего Playwright и Chrome DevTools,
остаются отдельными для каждого агентского сеанса.

Документ описывает рабочее окружение разработчика, а не продукт Cubica. Он не
разрешает останавливать чужие терминалы, браузеры, агентские сеансы или
системные службы.

## 1. Принятая операционная модель

| MCP | Размещение | Причина |
| --- | --- | --- |
| Context7 | официальный удалённый Streamable HTTP endpoint | сервис читает документацию и не требует локального процесса на каждого агента |
| Playwright MCP | отдельный локальный процесс на агентский сеанс | браузерный контекст, вкладки и cookies не должны пересекаться между агентами |
| Chrome DevTools MCP | отдельный локальный процесс на агентский сеанс | соединение с целью Chrome и состояние DevTools принадлежат одному агенту |

«Общий Context7» означает общий сетевой сервис, а не совместное использование
одного STDIO-канала несколькими агентами. Codex открывает собственное HTTP-
соединение, но не запускает локальный `npx @upstash/context7-mcp` для каждого
субагента.

Не создавайте локальный прокси или собственный пул только ради экономии памяти:
это добавит маршрутизацию сессий, наблюдаемость, восстановление и новую точку
отказа без дополнительной продуктовой ценности.

## 2. Подключение общего Context7

Изменение пользовательского или проектного `config.toml` — отдельная операция
настройки рабочего места. Запрос подготовить документацию не разрешает агенту
самостоятельно менять эту конфигурацию.

До изменения явно выберите один источник:

- `~/.codex/config.toml` — рекомендуемый общий профиль Codex на текущем хосте;
- `.codex/config.toml` доверенного проекта — только если Context7 намеренно
  должен быть проектной настройкой.

Не запускайте параллельно `codex mcp add`, `codex mcp remove` или другой
редактор того же файла. Сохраните защищённую резервную копию выбранного файла
в его каталоге, не выводя содержимое в терминал и не перенося его в `.tmp`:
конфигурация может содержать секреты других MCP. Используйте редактор с
атомарным сохранением файла.

Полностью замените существующую таблицу Context7 с `command` и `args` на:

```toml
[mcp_servers.context7]
url = "https://mcp.context7.com/mcp"
bearer_token_env_var = "CONTEXT7_API_KEY"
startup_timeout_sec = 10
tool_timeout_sec = 60
enabled = true
```

`CONTEXT7_API_KEY` должен быть непустым и передаваться окружению Codex из
пользовательского хранилища секретов. Не записывайте значение ключа в
репозиторий, `http_headers`, аргументы процесса или журналы. Не используйте
`codex mcp get context7 --json` для старой записи: версия 0.147.0 может вывести
буквальные значения старых `env` или `args` вместе с секретом.

Анонимное подключение является отдельной осознанной конфигурацией без
`bearer_token_env_var`. Указанный выше профиль не переключается на него
автоматически, если `CONTEXT7_API_KEY` отсутствует.

Не отправляйте Context7 секреты, персональные данные или закрытый код проекта:
запрос уходит во внешний сервис и должен содержать только название библиотеки и
узкий вопрос по её публичной документации.

## 3. Проверка общего Context7

Сначала проверьте обязательное окружение, не выводя MCP-записи:

```bash
if [ -z "${CONTEXT7_API_KEY:-}" ]; then
  printf 'CONTEXT7_API_KEY is not set\n' >&2
  false
fi
```

При ошибке остановите настройку и передайте ключ через пользовательское
хранилище секретов до запуска Codex.

После этого завершите старые Codex-сеансы и из отдельного терминала запустите
новый строгой командой:

```bash
codex --strict-config
```

Успешный запуск TUI подтверждает строгий разбор конфигурации. В TUI выполните
`/mcp`: Context7 должен иметь сетевой транспорт и адрес
`https://mcp.context7.com/mcp`. Не публикуйте диагностический вывод, если клиент
показывает заголовки или значения окружения.

В новом сеансе выполните один узкий запрос публичной документации через
Context7. Успешный реальный ответ является обязательной проверкой: строгий
разбор TOML сам по себе не доказывает доступность endpoint или корректность
ключа.

Только после этого удалите точную резервную копию конфигурации. При ошибке не
запускайте локальный Context7 автоматически: сначала выполните откат из раздела
7 и определите, является ли причиной сеть, ключ или конфигурация.

## 4. Ограничение жизненного цикла субагентов

В Codex CLI 0.147.0 наблюдались локальные STDIO MCP, которые продолжали жить
после состояния `completed` у встроенного субагента. При этом доступные
интерфейсы не дают устойчивого соответствия между логическим субагентом и
конкретной группой процессов операционной системы.

Снимок процессов до и после запуска агента этого соответствия не создаёт:

- основной Codex или другой агент может лениво запустить MCP в том же окне;
- все такие процессы имеют общего родителя `codex`;
- PID и PGID могут быть переиспользованы;
- `comm` и время запуска не являются дескриптором владения.

Поэтому запрещено определять «процессы субагента» разницей двух снимков и
посылать найденному PGID `SIGTERM` или `SIGKILL`. Дополнительные проверки PID,
PPID и времени уменьшают вероятность ошибки, но не устраняют гонку между
проверкой и сигналом.

Точечная автоматическая очистка станет допустимой только при наличии границы,
созданной в момент запуска и поддерживаемой всем жизненным циклом:

- дескриптора `subagent -> processes`, предоставленного Codex; либо
- отдельного cgroup/systemd scope, который Codex создаёт для конкретного агента
  и закрывает после его окончательного завершения.

Добавлять собственный cgroup-supervisor вокруг встроенных субагентов сейчас не
следует: это новый привилегированный инфраструктурный слой, тогда как более
простой безопасный путь уже существует.

## 5. Безопасная очистка процессов

До появления устойчивой границы владения применяется очистка всего сеанса:

1. дождитесь результатов всех субагентов текущего Codex;
2. убедитесь, что ни один из них не работает и не будет продолжен;
3. сохраните нужные результаты и закройте основной Codex штатной командой
   интерфейса или закрытием принадлежащего ему терминала;
4. из отдельного терминала проверьте, что подтверждённый процесс этого Codex и
   его локальные MCP завершились;
5. запустите новый Codex-сеанс с удалённым Context7.

Закрытие всего сеанса является безопасной границей, потому что уничтожается
сам подтверждённый владелец дерева, а не угаданная группа одного субагента. Если
сеанс нельзя закрыть сейчас, оставьте его MCP работающими: занятые ими страницы
swap не являются мусором, пока жив владеющий процесс.

Не используйте `pkill node`, `pkill npm`, `killall`, поиск только по имени,
`swapoff -a` или `drop_caches`. Не завершайте пользовательские браузеры, другие
терминалы и агентские сеансы, `necobox`, `necoray` или `vray`.

Тестовые процессы Cubica и явно созданные тестом группы не относятся к этому
ограничению: их запускающий код владеет устойчивым дескриптором процесса и
обязан очищать свою группу по правилам
[runbook восстановления сервисов](./service-recovery-runbook.md).

## 6. Диагностика памяти

До и после штатного закрытия сеанса снимите одинаковые показатели:

```bash
free -h
awk '/MemAvailable|SwapTotal|SwapFree/ {print}' /proc/meminfo
```

Для read-only диагностики разрешено посмотреть PID, PPID, PGID, время запуска и
`comm` подтверждённого дерева. Не сохраняйте и не публикуйте полные `args` или
`/proc/*/environ`: там могут находиться ключи и строки подключения.

Общие показатели памяти могут одновременно меняться из-за других программ.
Swap основного Codex или активного MCP нельзя точечно «очистить» без завершения
процесса. Не переносите весь swap обратно в память: на хосте с 8 ГиБ это может
вызвать новый пик и завершение полезных процессов.

## 7. Откат и источники

Если удалённый Context7 недоступен, закройте новые Codex-сеансы, убедитесь, что
никто больше не изменял активный `config.toml`, и атомарно верните его точную
защищённую копию. Затем запустите новый сеанс со строгим разбором и проверьте
реальный запрос:

```bash
codex --strict-config
```

Возврат STDIO-конфигурации восстанавливает локальный Context7, но снова создаёт
отдельный процесс для каждого агентского сеанса. Не заменяйте сетевой сбой
самописным общим прокси без отдельного анализа безопасности и эксплуатационной
стоимости.

Поддерживаемые транспорты и параметры Codex:

- [Context7: конфигурация клиентов](https://github.com/upstash/context7/blob/master/docs/resources/all-clients.mdx)
